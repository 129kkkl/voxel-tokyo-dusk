## 0. 为什么还要再升一级

Phase 1B 把「有机空城 + 占位盒子」救成了「有机满城 + 有窗密度城」：plotUseRate 88%、claims 4009、地标落位、路侧道具上机、294k 实例 / 119fps。**密度问题已解。**

但用户反馈确认的两个核心审美问题仍然刺眼——**建筑物不好看**、**城市布局杂乱**。对照 phase1b 六机位与参考图，根因不在数据层（`src/city/` 的 claim/audit/路网骨架是资产），而在**建筑形态学**与**城市形态学**两层。

### 0.1 建筑不好看（主诉 1）——现象 → 代码根因

| # | 现象（截图证据） | 代码根因 |
| --- | --- | --- |
| A-1 | 天际线是「钉板」：大量相似高度方柱，无低-中-高层带 | `districts.js heightFor` 分区内**均匀随机**，高度空间不相关；`facade.paintBody` 始终直棱柱，无退台/裙房/冠部 |
| A-2 | 立面 = 色块 + 稀疏亮窗点，不是「窗的织物」 | 暗窗**不生成**实例 → 大片空白墙 + 随机亮点；窗步长 3、亮灯率 0.14–0.35，构不成参考图的密集窗格网 |
| A-3 | 近景更丑：白盒住宅 / 黑柱办公 | 住宅无坡屋顶/出檐/阳台体量（只有一条 1 格阳台板）；`style` 的 curtain/mullion/core 视觉差异过小（只是窗概率微调） |
| A-4 | 屋顶秃、轮廓平 | 只有「压边 + 45% 小水箱/天线」；无女儿墙、无机电层、无冠部、无屋顶设备群 |
| A-5 | 楼层读不出来 | `bands` 上限 6 且同色系微差；无每 2–3 层楼板暗线，无窗上下框 |
| A-6 | 办公近景是黑柱 | `WALL.office` 含 `0x27344b/0x3d4148` 深色，暮色下几乎无受光面细节；亮窗又少，形成「黑板撒芝麻」 |
| A-7 | 地标外的塔楼同质化 | `buildOffice` 随机三选一 style，无「板楼/塔楼/双塔/带裙房」体量原型 |

### 0.2 布局杂乱（主诉 2）——现象 → 代码根因

| # | 现象（plan/cbd 截图） | 代码根因 |
| --- | --- | --- |
| B-1 | 平面是「碎裂玻璃 / 蜂窝」，均质细胞无层级 | `CFG.VORONOI + LLOYD_ITERS=3 + DMIN 18/36` 产出全城尺度相近的多边形街区；缺「超大街区 / 小街区」双尺度 |
| B-2 | 高度无秩序 → 钉板天际线 | 无高度场（height field）；邻里高度不相关，CBD 28–72 均匀抽、住宅 4–8 均匀抽 |
| B-3 | 街墙不连续：建筑各自为政 | `buildPlots` 按 face 独立切带、`spacing` 随机、`setback` 固定 1–2 → 无统一建筑线，临街界面进进出出 |
| B-4 | 道路标线呈锯齿噪点 | `ground.js` 标线沿 oblique `dirAngle` 逐格画，斜向路出现阶梯噪点 |
| B-5 | 分区「带状 + 散点」，邻里感弱 | `city/districts.js` 径向带 + quota 散布；entertainment/electronics/traditional 等以「补丁」形式砸进 expendable 区，缺过渡 |
| B-6 | 街区内部空洞/碎块 | `SLIVER_AREA=120` 吸收 + `PLOT_FREE` 填充是补丁式；无庭院/停车场/里弄的正经内院结构 |
| B-7 | 高度与类型脱钩 | `HIGH_RISE_RESI` 40% danchi 60% house 但高度带 12–24 给 house 也抽到 24，住宅区出现「瘦高白柱」（resi 截图刺眼） |

### 0.3 一句话根因

> **Phase 1B 解决了「有没有」，没解决「像不像」。**  
> 建筑缺**形态语言**（体量原型 + 立面构成 + 屋顶轮廓），城市缺**形态秩序**（高度场 + 街墙 + 街区尺度层级）。

## 1. 升级定位：从「密」到「美」

**一句话目标**：保留有机数据层与 claim 契约，把「有肉的色块城」进化成「有肌理、有天际线秩序、有黄昏窗光织物的东京」。

对照参考图的三层观感目标：

| 观看距离 | 现状 | 目标 |
| --- | --- | --- |
| **远看 pano** | 钉板方柱海 + 两座地标 | **三段式天际线**：低层暖窗地毯 → 中层簇群 → 少数英雄塔；东京塔为唯一橙色锚点；窗光连成「城市亮起来」的织物 |
| **中看 district** | 类型靠猜 | **街区性格可辨**：CBD 冷灰玻璃塔群 / 住宅暖色坡顶肌理 / 站前中高层店招带 / 港工业长条+吊机 / 传统区暖木低层 |
| **近看 street** | 空白盒 + 芝麻窗 | **立面有构成**：楼层暗线、窗格阵（含暗窗）、底层店面、阳台/雨棚体量、屋顶女儿墙+设备；放大后仍成立 |

## 2. 可验收目标（升级完成的定义）

离线单文件 `体素东京-暮色.html` 同时满足：

1. **天际线**：pano 可读出低-中-高三段；不再是一片等粗方柱；东京塔/天空树仍是锚点且不被普通楼淹没  
2. **立面**：resi / mainstreet 机位可读出楼层与窗格阵（**含暗窗格**），住宅有屋顶轮廓（坡顶或女儿墙+出檐）  
3. **窗光织物**：全景出现参考图式「地毯感」暖窗密度，而不是稀疏亮点  
4. **平面秩序**：`?plan=1` 可读出主干-次干-支路层级与超大街区，不再是均质蜂窝；街墙对齐  
5. **高度相关性**：同街区邻接建筑高度差有约束（见 §5.2），CBD 出现明确高度梯级  
6. **类型辨识**：CBD / resi / harbor / station / traditional 五区形态一眼可辨  
7. **预算**：glow ≤ 15%；总实例 ≤ 800k；`?cam=pano` FPS ≥ 45（目标机）  
8. **硬约束不回退**：audit 五类 = 0；claim 不压路/水/轨；同 seed 两次加载像素一致；`npm test` 全绿  
9. **六机位 + plan 终验**：pano / cbd / mainstreet / resi / harbor / station / plan 人工逐张判读通过  
10. **参考图色温**：黄昏暖冷对比——橙紫地平、深蓝天顶、暖窗；不是正午灰，也不是夜店紫

## 3. 总原则

1. **不推倒 `src/city/` 骨架**。路网因果（环+放射+有机次级）、水系、claim/audit 契约保留；布局「秩序化」是**在现有骨架上加场（field）与规则**，不是重写生成器。  
2. **唯一落位入口**仍是 `CITY.claim` / `claimFree`。  
3. **先形态、再肌理、再光、再生活**。每阶段 `build:single` 可出图，禁止长期不可运行。  
4. **预算优先给「面」**：窗格阵、楼层线、街墙对齐比单个地标更影响观感；地标的精修在 M3 集中做。  
5. **暗窗也是造型**。允许暗窗以非 glow 实例（深色玻璃体素）入批——这是从「芝麻墙」变「窗织物」的关键，实例预算向此倾斜。  
6. **参考图是气质基准**：密度感、层次感、窗光织物、色温；不是像素抄写。  
7. **每一阶段独立验收**，不通过不进下一阶段。

## 5. Phase M —— 建筑形态学复兴（主战场 1）

**目标**：每一栋建筑从「色块+芝麻」变成「有体量、有楼层、有窗格、有屋顶轮廓的类型原型」。

### 5.1 M1 体量原型（massing）——消灭直棱柱

新建 `src/build/massing.js`，提供可组合的体量原语（全部在 claim 矩形内）：

| 原语 | 几何 | 用于 |
| --- | --- | --- |
| `podiumTower` | 裙房 h/4 全幅 + 塔楼收进 25–35% | 办公、站前、danchi 塔 |
| `setbackStack` | 2–3 段递进收分，每段收 15–25% | 高层办公、地标邻楼 |
| `slabBlock` | 板楼：长向满幅、短向薄 | danchi、医院、学校 |
| `twinBar` | 双柱 + 连接体/中缝 | 都厅式、大型办公 |
| `houseCluster` | 1 主屋 + 1 附属（小屋/车库） | 低层住宅 |
| `shopShed` | 窄面深、平屋顶女儿墙 + 屋顶广告位 | 商业/娱乐/电器 |

规则：
- claim 面宽 `w<6` 强制 shed/house 系，禁止塔楼（消灭瘦高白柱）  
- 高度 ≥24 且 `min(w,d)≥8` 才允许 `setbackStack`  
- 裙房沿 `plot.face` 出挑 1 格，形成街墙底座  

### 5.2 M2 立面构成（facade v2）——窗的织物

重写 `facade.js` 的窗与楼层系统（关键差异点）：

| 要素 | 现状 | 目标 |
| --- | --- | --- |
| 暗窗 | 不生成 | **生成深色玻璃体素**（`WINDOW.dark = [0x1a2230, 0x222a3a, 0x2a3344]`，glow=false）——立面从空白墙变窗格阵 |
| 窗格 | 步长 3，1 体素 | 开间步长 2–3、层高步长 2–3；每窗 1–2 体素；办公幕墙可 2 层通高 |
| 楼层线 | bands≤6 同色微差 | **每 2–3 层**一圈 `shade(wall, 0.82)` 暗线；顶层压檐 `shade(wall, 1.08)` |
| 竖梃 | mullion 只减窗概率 | 每 2–3 开间一条贯通竖线（墙色打断） |
| 窗光 | 稀疏亮点 | 亮灯率 30–50%（暗窗已有造型托底）；按楼层带衰减保留；暖 7:冷 3 |
| 四面窗 | face+对面，够宽加一侧 | **四面都画**（至少暗窗）；临街两面亮灯率高、背面低 |
| 底层 | 1–2 层暗色 | 店面：橱窗横带（小面积 glow）+ 雨棚 1 格出挑 + 门洞暗块 |
| 阳台 | 1 格板 | 体量阳台：板 + 1 格栏杆；住宅 60%、danchi 走外廊 |

立面模式重定义（视觉差异必须明显）：

| mode | 视觉特征 | 用于 |
| --- | --- | --- |
| `curtain` | 全面密窗格 + 水平楼板线，墙色深灰蓝，窗占立面 ≥55% | CBD |
| `mullion` | 密窗 + 每 2–3 开间贯通竖梃 | 副都心、站前 |
| `punched` | 规整窗洞阵 + 大片墙，暖墙色 | 住宅、团地、公共 |
| `gallery` | 外廊水平带 + 重复单元门 | danchi |
| `shopfront` | 底层通长店面 + 上层 punched/curtain | 商业街 |

## 6. Phase U —— 城市形态秩序（主战场 2）

**目标**：平面不再是「碎裂玻璃」，天际线不再是「钉板」；街区有尺度层级、街墙有连续性、高度有秩序。

> 允许改的是「场与规则」，不是重写 `roads/water/blocks` 的生成因果。所有 CFG 变更须过形态不变量测试。

### 6.1 U1 高度场（height field）——消灭钉板

新建 `src/city/heightField.js`（或 `src/build/heightField.js`，只读 CITY）：

```
h_target(block) = f(距 CBD 距离, 距副都心距离, 距车站距离, 分区基带, 噪声)
```

| 规则 | 说明 |
| --- | --- |
| 基带 | 分区给出 `[lo, hi]`（沿用 HEIGHT 表，但住宅/传统按 §5.4 收紧） |
| 梯级 | 距 CBD/副都心/主站越近取带内越高；向外单调衰减 |
| 空间自相关 | 对 block 质心做值噪声（尺度 ~80–120），贡献 30% 权重 → 邻里高度相近 |
| 邻接约束 | 同街区相邻 plot 高度差 ≤ 40% 带宽；临街同段高差 ≤ 8（街墙） |
| 英雄塔点缀 | 每 CBD/副都心允许 1–3 栋拔尖到带顶 +10%（形成天际线峰，而非全体等高） |
| 团地/板楼 | 整街区共享 1–2 个高度档，禁止逐栋乱抽 |

输出写入 `block.hBand` / `plot.h`，`districts.js` 只消费不再 `rng.int` 乱抽。

### 6.2 U2 街区尺度层级——消灭蜂窝

在**不改路网拓扑**的前提下引入双尺度秩序：

| 策略 | 做法 | 预期观感 |
| --- | --- | --- |
| 次干降噪 | `MINOR_DELETE_P` 0.2 → 0.28–0.32（压碎路）；或对「围合面积 < 阈值」的 minor 环优先删 | 平面留白增多，主干更醒目 |
| 超大街区 | 选定 6–10 个大 block（公园/大学/站前/巨蛋邻域）禁止切碎路，内部只走 `PLOT_FREE` + 内院 | 出现「超级街区」锚点 |
| 内院结构 | 有 alley 的 block：外圈临街建面、内圈 `PLOT_FREE` 做庭院/停车场/里弄，禁止内圈再插临街假面 | 街墙在外、空在内 |
| 碎块政策 | `SLIVER_AREA` 120→180；碎块只做口袋绿地/停车场，不塞建筑 | 消除菱形怪楼 |

### 6.3 U3 街墙与建筑线（street wall）

改 `src/city/plots.js` 切分规则（行为受测试保护）：

| 规则 | 现状 | 目标 |
| --- | --- | --- |
| 建筑线 | 每 band 随机 spacing + 固定 setback | **同 roadId 同 face 的连续段共用一条建筑线**（取该段 front 带众数） |
| 间距 | `spacing:[7,13]` 等纯随机 | 基准间距 × (1 ± 15%)，同段方差收窄 → 面阔节奏 |
| 退线 | 1–2 | 按道路等级：RING/RADIAL 3、ARTERIAL 2、MINOR 1；同段一致 |
| 转角 | 无 | 街角 plot 允许双向店面（`face` + 相邻 face） |
| 面阔约束 | 无 | 住宅 5–9、商业 6–12、办公 8–16；超出切两栋 |

### 6.4 U4 分区性格与过渡

| 任务 | 做法 |
| --- | --- |
| 性格锁定 | 每 district 绑定「高度带 × 体量原型 × 立面模式 × 屋顶套件 × 配色」五元组（消费 Phase M 类型库） |
| 补丁收敛 | entertainment/electronics/traditional 的 quota cluster 半径收紧，禁止散点式 `hash` 硬砸 |
| 过渡带 | 相邻不同 district 的边界 block 高度取两者较低带、类型取更安静一侧（办公→住宅过渡为小公寓） |
| commercial 补缺 | Phase 1B 记录「commercial 几乎缺失」——把主站 80–150 环带的 STATION_FRONT 再细分为 commercial 主街走廊 |

### 6.5 U5 地面可读性

| 任务 | 做法 |
| --- | --- |
| 标线去噪 | 车道线沿道路折线参数化画，**禁止 oblique 逐格阶梯**；斑马线只在路口；虚线用 run-length |
| 人行道 | 统一高出 1 格 + 路缘石暗线；消除与车道的锯齿咬边 |
| 街区地坪 | 按 district 2–3 低饱和基色 + 8×8 瓦片明度微差；庭院/停车场语义色块 |
| 水面 | 保持 glow=false；岸线加深色护岸线，桥墩入水 |

- [ ] 标线无锯齿噪点  
- [ ] audit 0；形态不变量测试全绿（可加新测试锁高度相关性/街墙对齐）  
- [ ] blocks 数仍在 1100–1600 带内或有记录说明

## 7. Phase L —— 黄昏光织物

**目标**：全景出现参考图的「城市亮起来」地毯感 + 黄昏暖冷对比。

| # | 任务 | 要点 |
| --- | --- | --- |
| L1 | 窗光织物 | 依赖 M2 暗窗托底后，亮灯率 30–50%；低层更亮；暖 7:冷 3；远景 LOD 可合并小窗为光斑带 |
| L2 | 天空终调 | 顶 `0x0b1026` → 中 `0x1a2750` → 地平暖 `0xc47a3a` / 藕紫 `0x6b4a6e`；`sky.js` 渐变与雾同源 |
| L3 | 雾与远景 | FogExp2 `0x3a3040` 密度微调；远山剪影与雾融合；近处不过分闷 |
| L4 | 主光 | 夕阳 `0xffa050` 与天空暖侧同方位；半球光补冷；**提亮建筑受光面**（解 A-6 黑柱） |

| L6 | 点光 | 三塔点光保留；增加 2–4 个街区级微弱点光（站前/娱乐）烘托夜感，数量克制 |

**验收**：pano 对照参考图色温与窗光密度主观达标；glow ≤15%；不是夜店紫。

## 15. 决策默认值（执行前确认）

1. **视觉方向**：黄昏写实密度 + 窗光织物；娱乐区局部彩色招牌；glow ≤15%  
2. **布局**：保留有机骨架，用「高度场 + 街墙 + 街区层级」加秩序，不重写生成器  
3. **暗窗**：以非 glow 深色玻璃实例落地（实例预算的主要增量），这是立面观感的第一杠杆  
4. **住宅**：低层锁 3–6 层 + 坡顶/出檐，宁可矮而像，不要高而丑  
5. **性能**：并行 Phase P，不阻塞 M/U 视觉主路径  
6. **交付定义**：六机位+plan 终验 + 数字验收 + 单文件三者齐全才算「升级完成」
