## 0. 现状诊断：为何仍未达预期

Stage 1A **做对了城市骨架，做丢了城市皮肉**。

| 层 | 状态 | 结论 |
| --- | --- | --- |
| 数据层 `src/city/*` | 有机路网 / 弯河港湾 / 街区地块 / `claim` 审计五类为 0 | **保留，不推倒** |
| 地面 `ground.js` | 读 CITY 铺装 + 挡土墙 | 结构可用，实例数超标 |
| 建筑视觉 `cityBuild.js` | **占位盒子**：单色体块 + 稀疏单面窗 | **未达预期的主因** |
| 旧视觉模块 | `residential/skyscrapers/street/park/special/shrine/landmarks` | **孤儿代码**：仍 import 已删除的 `ground.js` 常量，不在 `main.js` 导入图内 |
| 动态与氛围 | 电车有、车流/行人无；天空仍旧；六机位未终验 | 阶段 2–4 未启动 |
| 性能 | CITY 冷跑 ≈2.3s（目标 400ms）；地面实例 ≈253k（目标 ≤135k） | 债务未清 |

**一句话根因**：有机布局已落地，但渲染层被临时 `cityBuild.js` 接管后，原 README 承诺的「密集日式都市」变成了色块占位；旧精致模块因依赖断裂被整体旁路。

**参考图给的目标气质**（与「去霓虹」不冲突，而是更准确）：

- **不是**赛博霓虹垃圾场，**是**黄昏下的真实东京密度
- 天际线：一座主塔（暖橙发光）+ 若干商务区高塔 + 大量中低层填充
- 窗光密而不炸：暖黄/少量冷白，不是整面霓虹
- 天空：深蓝 → 橙紫渐变，远山剪影，薄雾
- 地面：道路网清晰、绿地成片、水体有岸线、轨道有体量
- 整体 **密度感** 与 **层次感** 比单体细节更重要

## 1. 升级目标（可验收）

升级完成后，离线单文件 `体素东京-暮色.html` 应同时满足：

1. **形态**：`?plan=1` 可读出环+放射+有机次级网、弯曲河港、不均街区（Stage 1 已过，不回退）
2. **密度**：全景机位下城市「满」——建成区覆盖率高，无大片空地荒漠；claims 建筑覆盖率 ≥ 目标
3. **层次**：CBD/副都心高塔、站前中高层、住宅低层、工业仓储、公园绿地一眼可辨
4. **地标**：东京塔/天空树/都厅/神社几何精致度回到或超过改造前水平，且不压路
5. **街道**：路灯、电线、贩卖机、信号灯、车辆、樱花、桥灯沿真实路网出现
6. **氛围**：黄昏天光 + 暖雾 + 窗光分级 + 地标点光，接近参考图色温
7. **动态**：环线电车行驶；主干车辆沿车道移动（可选行人）
8. **数字**：audit 五类 = 0；体素级反查压路体素 = 0；总实例 ≤ 660k；glow ≤ 15%；`?cam=pano` FPS ≥ 现状
9. **确定性**：同 seed 两次加载像素一致
10. **六机位终验**：pano / cbd / mainstreet / resi / harbor / station 全部截图通过人工判读

## 2. 总原则（全阶段约束）

1. **不推倒 `src/city/`**。布局与 claim 契约是资产；升级是在其上重建视觉与生活层。
2. **唯一落位入口**仍是 `CITY.claim` / `claimFree`。任何新生成器禁止绕过。
3. **先可见、再精致、再动态**。每阶段必须能 `npm run build:single` 并出图；禁止长期不可运行的中间态。
4. **视觉模块化重写，不硬拧旧文件**。旧 `residential.js` 等可拆零件函数迁入 `src/build/`，但对外只暴露 `build*(vox, CITY, rng)`，内部布局只读 CITY。
5. **预算优先给「面」**。窗光、屋顶、路面细节比单个地标更影响全景；地标的精致度在 Phase 2 集中做。
6. **每一阶段有独立验收清单**，不通过不进下一阶段；性能债务可并行，但不得阻塞视觉主路径超过一个阶段。
7. **参考图是视觉基准，不是像素抄写**。体素尺度允许简化，但色温、密度、层次必须对齐。

## 5. Phase 1B — 视觉密度复兴（主战场）

**目标**：把「有机空城」变成「有机满城」。全景一眼要有城市，不是棋盘上的盒子。

### 5.1 架构：新建 `src/build/` 渲染库

废弃 `cityBuild.js` 的单文件占位逻辑，拆成：

```
src/build/
  palette.js      分区配色 + 窗光 + 材质语义（Phase 2 再扩类型）
  facade.js       立面零件：窗阵、竖梃、楼板暗线、底层店面、屋顶设备
  types/
    house.js      町屋/小公寓
    shop.js       商业楼 + 招牌
    office.js     写字楼（幕墙/竖梃/核心筒/退台）
    danchi.js     团地塔楼
    industrial.js 仓库/厂房/油罐
    civic.js      学校/医院/公共建筑
    landmark.js   三塔+神社+巨蛋（Phase 2 精修，Phase 1B 可先调用增强版）
  districts.js    分区 → 类型分发
  props/
    street.js     路灯/电线杆/贩卖机/信号灯/公交站/车辆静态
    green.js      树/公园/樱花/围墙
    rail.js       轨道/车站/接触网（基于 CITY.rail）
  index.js        placeFromCity 重构版
```

`main.js` 只 import `src/build/index.js`。

### 5.2 密度与地块策略（关键）

当前问题：`claim` 失败或 plot 未覆盖导致大片空地。

| 策略 | 做法 |
| --- | --- |
| plot 使用率 | 逐 district 统计 claim 成功率；对失败 plot 降尺度重试（w/d −1，最多 3 次）；仍失败记 HUD |
| 街区填充 | 对 `PLOT_FREE` / 未切出 plot 的街区内部：按分区概率放小构筑（停车场、庭院、变电、小棚），走 `claimFree` |
| 住宅区密植 | `LOW_RISE_RESI` 一 plot 可放 1–2 栋（主屋+附属）；间距用面阔而非大退线 |
| 绿地不空洞 | 公园至少有：地坪变色 + 树 + 围墙/步道之一；禁止纯色块 |
| 工业/港口 | 大 footprint 长条仓库 + 集装箱堆 + 吊机剪影 |
| 空地红线 | 全景下建成区外的「纯地坪」面积占比进入 HUD，目标逐步压低 |

### 5.3 立面最低标准（Phase 1B，不必等 Phase 2）

每个建筑至少具备：

1. 主体体块（分区高度带）
2. **四面**窗阵或至少两面朝街面（禁止只画 +z）
3. 底层 1–2 层店面/车库/围墙差异色
4. 屋顶：压边 + 水箱/机房/天线之一（概率）
5. 窗光：按楼层带亮度衰减（低层更亮），亮灯率 25–45%，暖主冷辅
6. 分区色差：CBD 灰蓝、住宅暖米、娱乐粉紫点缀、工业冷灰

### 5.4 地标增强（仍受 claim 约束）

| 地标 | Phase 1B 目标 |
| --- | --- |
| 东京塔 | 桁架斜撑可读、橙段发光、展望台、航空信标（保留现有动态 blink） |
| 天空树 | 收分塔芯 + 螺旋点阵/条带外壁、tripod、青蓝观景台 |
| 都厅 | 双塔网格立面、分层亮灯、中缝 |
| 神社 | 鸟居列、参道、灯笼串、主殿+屋檐层次、五重塔剪影 |
| 巨蛋 | 连续壳面 + 透光带，而非柱子圈 |

### 5.5 轨道与站（Phase 1B 范围）

- 桥墩 + 托梁 + 双轨 + 接触网杆与导线
- 车站：雨棚、站台、发光站名牌、落地台阶；**站台不得叠在轨道带上**（修 Stage 1A 遗留）
- `createTrain` 沿 `CITY.rail` 曲线行驶（已有逻辑保留，校验高度）

### 5.6 街道静态细节（Phase 1B 尽量上）

- 沿 `CITY.roads` 折线：路灯（按 `ROAD.*.lampGap`）、电线杆+架空线、信号灯、公交站
- 人行道上的贩卖机、消防栓、小树
- 桥头栏杆与桥灯；河岸樱花步道（`RECLAIM` 格）
- 静态车辆按 `dirAngle` + 车道偏移摆放（为 Phase 3 动画铺路）

### 5.7 地面轻量修正（不等 Phase P）

- 路面标线沿 `cell.dirAngle`，取消随机感
- 水面去自发光（规格 §11.5）
- 街区分区地坪 2–3 个低饱和基色 + 8×8 瓦片明度微差
- 努力方向：地面实例向 ≤150k 靠拢（完整优化见 Phase P）

## 9. Phase P — 性能与构建债务（并行）

| 债务 | 现状 | 目标 | 方向 |
| --- | --- | --- | --- |
| CITY 构建耗时 | ≈2.3s | ≤ 400–800ms | 热点 profiling（roads Voronoi / blocks flood / plots）；TypedArray 复用；可分帧 yield；避免重复分配 |
| 地面实例 | ≈253k | ≤ 135k | 强化 run-length：同 type+colorVariant+y 合并；地形量化保持街区同高；减少逐格墙 |
| 总实例预算 | — | ≤ 660k | 建筑细节用合并 box/缩放实例；暗窗不生成 |
| 遗留 consumer | 孤儿文件 | 0 误用 | Phase 1B/2 迁入 `src/build/` 后删除或归档 legacy |
| debug 反查 | 未完整接 | 可用 | `vox.keepRecords` + 投影 cell 统计 |

**约束**：Phase P 不得改布局语义（路网形态、水系、分区配额）除非单独 RFC；只许优化实现。
